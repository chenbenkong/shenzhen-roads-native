# 深城纪 · 一路向海（原生版）

用 **Godot 4.7 + Vulkan** 重写的深圳开放世界驾驶游戏。同一份真实路网数据（OSM 深圳），
从 Web 版（Three.js）迁移到原生引擎，目标是**核显笔记本上流畅跑 60fps 以上**。

实测（AMD Ryzen 5 5600H 核显 Radeon Vega 7，默认「均衡」档 = 78% 渲染分辨率 + FSR 1.0）：

| 分辨率 | 帧率 |
|---|---|
| 1280×720 | 200+ FPS |
| 1920×1200（推荐窗口） | **约 103 FPS** |
| 2560×1600 | 约 72 FPS |
| 3200×2000（原生全屏） | 约 51 FPS（同分辨率优化前 24 FPS） |

（同一台机器上 Web 版是 80 FPS，原 Babylon.js 版本明显卡顿）

## 能做什么

- **驾驶**：8 种车型（轿车 / 跑车 / 越野 / 出租 / 厢货 / 巴士 / 卡车 / 警车），
  街机滑移手感（推头、甩尾、烧胎、手刹漂移），车身俯仰侧倾，撞建筑会掉车损
- **下车走路**：F 键下车，第三人称角色行走，Shift 奔跑，走回车边按 F 上车
- **开飞机**：湾翼双浮筒观光机，滑跑加速到 26 m/s 拉杆离地，可在海面起降
- **城市氛围**：64 辆 AI 车沿真实路网行驶（遵守单行、遇前车减速），96 个行人沿人行道行走
- **昼夜**：程序化天空，夜间建筑亮窗自发光、路灯光晕
- **地图**：M 键打开全城地图（金色 = 高速，灰 = 主次干道，绿 = 绿地，蓝 = 水体）
- **音效**：全部由代码实时合成（发动机随转速变调、风噪、胎噪、打滑、喇叭、碰撞），零音频素材

## 操作

| 场景 | 按键 |
|---|---|
| 驾驶 | `W/S` 油门刹车 · `A/D` 转向 · `空格` 手刹 · `C` 视角 · `R` 换车 · `F` 下车 · `B` 上飞机 |
| 步行 | `WASD` 移动 · `Shift` 跑 · `F` 上车 · `B` 上飞机 |
| 飞行 | `Shift/Ctrl` 油门 · `W/S` 俯仰 · `A/D` 滚转 · `Q/E` 方向舵 · `空格` 刹车 · `B` 下机 |
| 通用 | `M` 地图 · `N` 昼夜 · `H` 喇叭 · `F3` 调试信息 · `Esc` 设置面板 |
| 破解玩法 | `V` 作弊菜单（无敌 / 引擎强化 / 通缉星级 / 时刻快进 / 传送 / 统计） · `F5` 存档 · `F9` 读档 |
| 导航 | `M` 大地图上左键点选航点（右键清除），A* 算路，小地图与大地图同步画金色路线 |

## 运行

### 方式一：直接玩打包好的版本

```
release/深城纪-一路向海-win64/ShenzhenOpenRoads.exe
```
双击即玩，无需安装。

### 方式二：用编辑器开发

需要 Godot 4.7（[官网](https://godotengine.org/download)）。

```bash
godot --path . --import          # 首次：导入资源
godot --path .                   # 运行
```

### 方式三：自己导出 exe

需要 Godot 4.7 的导出模板（编辑器里 菜单 → 编辑器 → 管理导出模板 一键安装）。

```bash
godot --headless --path . --export-release "Windows Desktop" "build/ShenzhenOpenRoads.exe"
```

## 工程结构

```
scripts/
  main.gd            入口与主循环（驾驶 / 步行 / 飞行三种模式调度）
  core/              常量、输入
  data/              city.bin 解码器、城市数据索引、路网图与 A*
  world/             程序化纹理图集、分块世界、着色器材质、天空、资产工具
  game/              载具物理/外观、步行、飞机、AI 车流、行人、相机、音效
  ui/                城市地图烘焙、HUD、设置面板
shaders/             城市/镂空/光晕三个自定义着色器
tools/               资产转换（Node 脚本，见下）
data/                city.bin（2.45MB 城市数据）+ city-meta.json
models/              原项目自建模型（飞机 / 行人 / 交通车 / 棕榈 / 自行车）
```

## 资产转换工具

`models/` 里的部分是**转换产物**，源头是原项目自建的 glb（用了 meshopt 压缩与量化属性，
Godot 的 glTF 导入器不支持这两种扩展）：

```bash
npm install --no-save meshoptimizer   # 仅工具需要
node tools/prepare-assets.mjs         # 拆分行人/车/树 → *_plain.glb、ped_*.glb
node tools/glb-inspect.mjs x.glb      # 查看 glb 部件结构（调试用）
```

| 工具 | 作用 |
|---|---|
| `prepare-assets.mjs` | 按部件名拆分多材质 glb，烘顶点色，关节移到原点，输出 Godot 可读的单 primitive glb |
| `glb-flatten.mjs` | 把任意 glb（含 meshopt/量化）拍平成单 primitive + 顶点色 |
| `decompress-meshopt.mjs` | 仅解压 meshopt 扩展（调试用，产物仍受量化扩展阻塞） |

## 技术要点

- **世界数据**：2.45MB 二进制（建筑 15819 栋 / 道路 12202 条 / 路网 17065 节点 23135 边），
  运行期直接解码，无需预处理
- **分块合批**：640 米一块，近景完整几何（建筑立面开窗、道路标线、街灯、行道树），
  远景用盒体 LOD；每块一个 MeshInstance3D（多 surface），实测 draw call 约 130
- **程序化纹理**：18 层 128×128 的 Texture2DArray 全部由代码生成（含夜间亮窗掩码），
  零贴图下载
- **批量绘制**：AI 车流与行人用 MultiMesh，全部行人只占 3 个 draw call（躯干 / 手臂 / 腿分开，
  四肢绕关节摆动实现走路动画）
- **渲染路径**：Vulkan / mobile 渲染器。同一台 AMD 核显上 Vulkan 与 OpenGL 差距巨大
  （200+ FPS vs 7.7 FPS），因此默认走 Vulkan，不支持的机器由引擎自动回退

## 性能优化（核显向）

瓶颈经四档分辨率实测确认是**像素填充率**——核显没有独立显存，像素全靠共享内存带宽
（各分辨率下的吞吐都卡在 ~180~200 Mpix/s 的同一条线上）。因此优化全部围绕「每像素少算一点、
少画一点」展开：

| 手段 | 效果（3200×2000 实测） |
|---|---|
| 城市着色器改 `vertex_lighting`（建筑本就是均匀大平面，逐像素光照纯浪费） | +16%~30% |
| 关闭天空环境光探针（实时模式每帧重烘焙立方体 + 逐像素立方体采样） | +21% |
| 用解析式「假天光反射」补回反光（`graze` 近似，约 6 条 ALU 换掉一整套世界空间反射运算） | 观感持平，成本在噪声内（44.3 → 44.3 FPS） |
| 渲染分辨率 < 100% 时切 FSR 1.0 上采样 | 同档位帧率不变，锐度接近原生（43.4 → 43.3 FPS） |
| 修复「全新启动不套用画质档位」的 bug（原来首次运行总按原生分辨率渲染） | 默认档 24 → 51 FPS |

命令行可覆盖渲染缩放做实测：`ShenzhenOpenRoads.exe -- scale=0.6`（双线性）或 `-- fsr=0.6`（FSR）；
另有 `-- nofx` / `-- nofog` / `-- probe` 等诊断开关。
